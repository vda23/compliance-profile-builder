# Журнал изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — по [семантическому версионированию](https://semver.org/lang/ru/).

## [1.1] — 2026-10-05

Версия по результатам тестирования первой версии и доработка построения профиля по нормативному документу.

### Исправлено — корректность выгружаемых профилей

Все типы проверок были прогнаны через OpenSCAP со всеми полями, а имена и порядок полей сверены напрямую со схемами OVAL 5.11.2.

- Выгружаемые файлы не проходили проверку `oscap oval validate` и `oscap xccdf validate`. Причин было несколько:
  - не выводились обязательные элементы: `instance` у объекта «Содержимое текстового файла», `local_address` у прослушиваемых портов;
  - не выводился обязательный атрибут `comment` у тестов и переменных, если поле в форме оставлено пустым;
  - у шаблона `pattern` не было `operation="pattern match"` — файл при этом валиден, но сканер мог сравнивать регулярное выражение как обычную строку;
  - неверные имена полей: `gecos` вместо `gcos`, `passwd_complexity` вместо `password_complexity`, `clear_text_passwd` вместо `reversible_encryption`, выдуманные `lockout_bad_count` и `auditing_subcategory`, `user_right` вместо `userright` и другие;
  - неверный порядок полей у прав на файлы, пакетов DEB и RPM, сетевых портов.
- Поле «Право пользователя» Windows принимало произвольный текст, хотя в схеме это закрытый перечень `SE_*` — теперь выпадающий список.
- Подкатегории политики аудита Windows описаны по схеме: отдельное поле на подкатегорию со значениями `AUDIT_*`.
- Демонстрационный проект Windows не загружался в Kaspersky Vulnerability Management: он был создан ранней версией генератора. Проект пересобран по структуре эталона, подтверждённого разработчиком продукта.
- При выгрузке любой проект приводится к схеме автоматически: старый или импортированный проект с ошибками порядка элементов и атрибутов выгружается уже исправленным.
- Импорт не находил бенчмарк в архивах, упакованных через «Сжать папку», и в архивах из macOS со служебной папкой `__MACOSX`. Теперь такие архивы импортируются; для XCCDF 1.2 выводится понятное объяснение; при ошибке перечисляется содержимое архива.
- Изменение элемента при ошибке во введённых данных удаляло его безвозвратно. Добавлен откат.

**Проверено:** все типы проверок со всеми полями проходят `oscap oval validate`; весь каталог типовых проверок для DEB- и RPM-систем проходит проверку схем XCCDF и OVAL; проверки выполнены командой `oscap oval eval` на тестовой Linux-системе.

### Добавлено

- **Редактирование на каждом шаге**: объекты, состояния, тесты и переменные можно изменять, а не только удалять и создавать заново. Идентификатор и место элемента в файле сохраняются, ссылки на него не рвутся.
- **Профиль по нормативному документу**: загрузка DOCX, ODT или TXT, разбор на пункты, определение темы каждого требования, подбор проверок и сборка черновика профиля. Перед созданием показывается таблица разбора с уровнем уверенности; после — отчёт: созданные правила, организационные меры, несопоставленные пункты. Черновик помечен статусом `draft` и предупреждением, в идентификаторе каждого правила — номер пункта исходного документа.
- **Автоматическая нумерация** в DOCX и ODT: номера пунктов восстанавливаются из разметки списков. Заголовки разделов служат границами пунктов и подсказкой о теме.
- **База знаний**: тезаурус из 40 тем требований с формулировками на русском и английском, словарь синонимов, приведение словоформ. Ссылки на семейства документов: ФСТЭК, ГОСТ Р 57580.1, CIS Benchmark, NIST SP 800-53, ISO/IEC 27002, PCI DSS. Доступна для просмотра с поиском: «Справка и настройки» → «База знаний».
- **Каталог типовых проверок**: базовые проверки Linux и пакет по Рекомендациям ФСТЭК России по безопасной настройке ОС Linux (2022) — 40 пунктов, из них 29 проверяются автоматически.
- **Быстрый старт** при первом запуске: с чего начать, чем мастер отличается от конструктора, настройки подсказок, открытие примера. Доступен повторно по ссылке «Справка и настройки».
- **Пример для Linux**: демонстрационный проект «Базовая настройка Astra Linux», 12 проверок.

### Изменено

- Подсказки на шагах мастера показываются один раз для всех проектов, а не заново в каждом. Всплывающие подсказки можно отключить полностью.
- Кнопка повторного показа подсказки подписана — одиночный «?» читался как кнопка закрытия.
- Окно «Добавить ещё?» можно отключить.
- Окончание `-oval.xml` в имени OVAL-файла добавляется автоматически.
- Адаптивная вёрстка: на узком экране и при увеличении боковая панель уходит наверх, широкие таблицы прокручиваются внутри себя.

### Известные ограничения

- Сервис не разграничивает пользователей: любой, у кого есть доступ к адресу, может изменить любой проект. Рекомендуется отдельный экземпляр на команду или обратный прокси с аутентификацией (пример — `deploy/nginx.conf.example`).
- Импорт поддерживает XCCDF 1.1. Формат XCCDF 1.2 и SCAP DataStream не поддерживаются.
- PDF для разбора не используется: текст в нём хранится как набор глифов, и кириллица часто извлекается искажённой.

## [1.0] — 2026-09-30

Первая версия.

- Веб-сервис для создания профилей соответствия XCCDF 1.1 / OVAL 5.11.2 и выгрузки их ZIP-архивом для импорта в Kaspersky Vulnerability Management.
- Пошаговый мастер из десяти шагов в порядке зависимостей элементов и режим конструктора.
- Встроенный валидатор, экспорт и импорт архивов.
- Интерфейс на русском и английском, светлая и тёмная темы.
- Сервер на стандартной библиотеке Python 3.5+, без внешних зависимостей; установка без доступа в интернет.
- Установка службой systemd с HTTPS, скрипт удаления.
