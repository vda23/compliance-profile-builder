# Compliance Profile Builder

Сервис для упрощения процесса написания профилей соответствия по стандарту OVAL.

## Назначение

Веб-сервис для создания профилей соответствия в формате XCCDF/OVAL и выгрузки их в виде ZIP-архива для импорта в Kaspersky Vulnerability Management.

Профиль собирается в браузере: пошаговый мастер проводит через все элементы проверки, подставляет идентификаторы и не даёт сослаться на несуществующий элемент. Черновик профиля можно получить автоматически — загрузив нормативный документ.

Готовый архив проверяется встроенным валидатором до выгрузки, а сами файлы соответствуют схемам XCCDF 1.1 и OVAL 5.11.2 — это проверено средствами OpenSCAP.

## Возможности

- **Мастер из десяти шагов** — в порядке зависимостей элементов: переменные, объекты, состояния, тесты, определения, правила, профили. На каждом шаге подсказка, а вместо пустого списка — переход к шагу, где нужный элемент создаётся.
- **Конструктор** — все разделы сразу, для правки готового или импортированного профиля.
- **Редактирование любого элемента** без потери ссылок на него.
- **Профиль по нормативному документу** — загрузите DOCX или ODT, и сервис разберёт его на пункты, определит тему каждого требования и соберёт черновик профиля.
- **База знаний** — темы требований и формулировки на русском и английском из документов ФСТЭК, ГОСТ, CIS, NIST, ISO и PCI DSS.
- **Каталог типовых проверок** для Linux, включая пакет по Рекомендациям ФСТЭК России по безопасной настройке ОС Linux.
- **Импорт и экспорт** ZIP-архивов, несколько профилей в одном бенчмарке.
- **Работа в закрытом контуре**: только стандартная библиотека Python, установка без доступа в интернет.
- Интерфейс на русском и английском, светлая и тёмная темы, адаптивная вёрстка.

## Что нового в версии 1.1

- Выгружаемые профили проходят проверку OpenSCAP: исправлены имена, порядок и обязательные элементы полей по схеме OVAL 5.11.2.
- Старые и импортированные проекты при выгрузке автоматически приводятся к схеме.
- Профиль по нормативному документу, база знаний и каталог типовых проверок.
- Редактирование элементов на каждом шаге.
- Быстрый старт, пример для Astra Linux, исправленные подсказки, адаптивная вёрстка.

### Поддерживаемые ОС

- Альт Сервер 10 (64-bit)
- РЕД ОС 8 (64-bit)
- Astra Linux Common Edition 2.12 (64-bit)
- Astra Linux Special Edition РУСБ.10015-01 (1.8, 64-bit), в том числе в режиме замкнутой программной среды
- Debian 11.x (64-bit)
- Platform V SberLinux OS Server 8.10.1 (64-bit)
- Platform V SberLinux OS Server 9.5.1 (64-bit)
- Ubuntu Server 22 (64-bit)

### Что нужно перед установкой

- 64-разрядная ОС из списка выше — x86_64 или aarch64
- `python3` версии 3.5 или новее
- `systemd` — для работы службы
- `openssl` — только для HTTPS
- 5 МБ свободного места на диске (место под создаваемые профили необходимо выделять дополнительно)

Доступ в интернет, pip, виртуальные окружения, база данных и отдельный веб-сервер не нужны.

## Установка

### 1. Скачайте архив и перенесите его на сервер

Архив `compliance-profile-builder-v1.1.zip` — на странице [Releases](https://github.com/vda23/compliance-profile-builder/releases/latest).

Перенесите его на сервер любым доступным способом — scp, съёмный носитель, внутренний файловый шлюз:

```bash
scp compliance-profile-builder-v1.1.zip user@server:/tmp/
```

### 2. Распакуйте архив и перейдите в директорию с установщиком

```bash
cd /tmp
unzip compliance-profile-builder-v1.1.zip
cd compliance-profile-builder
```

Если в системе нет `unzip`, подойдёт любой штатный архиватор, например:

```bash
python3 -m zipfile -e compliance-profile-builder-v1.1.zip .
```

### 3. Запустите установку

```bash
sudo bash deploy/install.sh
```

#### Скрипт выполнит

- проверку операционной системы и версии python3;
- копирование файлов в `/opt/compliance-profile-builder`;
- создание системного пользователя `cpbuilder` (без права входа в систему);
- выпуск самоподписанного HTTPS-сертификата, в который попадут IP-адреса сервера;
- создание и запуск службы `compliance-profile-builder`.

#### По завершении скрипт выведет адреса, по которым доступен сервис

```
https://127.0.0.1:8443/   (доступ с сервера)
https://10.0.0.15:8443/   (доступ по сети)
```

### 4. Откройте сервис в браузере

Перейдите по адресу из вывода установщика.

Браузер предупредит о недоверенном сертификате — это ожидаемо для самоподписанного сертификата. Нажмите «Дополнительно» → «Перейти на сайт».

Чтобы предупреждения не было, установите собственный сертификат по инструкции ниже.

## Параметры установки

Вывод списка: `bash deploy/install.sh --help`

Использование другого порта:

```bash
sudo bash deploy/install.sh --port 9443
```

Добавление собственного сертификата вместо самоподписанного:

```bash
sudo bash deploy/install.sh --cert /path/to/fullchain.pem --key /path/to/privkey.pem
```

Имя в сертификате и срок его действия:

```bash
sudo bash deploy/install.sh --cn profiles.example.local --cert-days 365
```

Без HTTPS (например, если TLS завершается на обратном прокси):

```bash
sudo bash deploy/install.sh --no-tls
```

Доступ только с самого сервера:

```bash
sudo bash deploy/install.sh --host 127.0.0.1
```

## Управление службой

```bash
systemctl status compliance-profile-builder     # состояние
systemctl restart compliance-profile-builder    # перезапуск
systemctl stop compliance-profile-builder       # остановка
journalctl -u compliance-profile-builder -n 50 --no-pager   # журнал
```

Данные (созданные профили) хранятся в `/opt/compliance-profile-builder/data/projects/` — по одной папке на проект, внутри обычные XML-файлы. Это же место нужно включить в резервное копирование.

## Обновление с версии 1.0

Распакуйте архив новой версии и запустите установку повторно — файлы сервиса будут заменены, созданные профили сохранятся:

```bash
sudo bash deploy/install.sh
```

Профили, созданные в версии 1.0, при выгрузке автоматически приводятся к схеме — пересоздавать их не нужно.

## Удаление

```bash
sudo bash deploy/uninstall.sh              # с подтверждением
sudo bash deploy/uninstall.sh --yes        # без подтверждения
sudo bash deploy/uninstall.sh --keep-data  # сохранить созданные профили
```

Удаляются: служба, каталог установки, системный пользователь `cpbuilder`.

## Работа с сервисом

### Быстрый старт

При первом запуске открывается экран быстрого старта: с чего начать, чем мастер отличается от конструктора, настройки подсказок. Кнопка «Открыть пример» сразу открывает демонстрационный профиль. Экран доступен повторно по ссылке «Справка и настройки» в боковой панели.

![Быстрый старт](docs/images/quick-start.png)

**Мастер** ведёт по шагам в нужном порядке и подсказывает на каждом — для первого профиля. **Конструктор** открывает все разделы сразу — для правки готового профиля. Данные у режимов общие: переключаться можно в любой момент.

### Профиль по нормативному документу

Кнопка «Загрузить документ…» в боковой панели. Поддерживаются DOCX, ODT и TXT, в том числе с автоматической нумерацией пунктов.

Сервис разбирает документ на пункты и до создания проекта показывает, какую тему требования он определил для каждого пункта и какую проверку предлагает, с уровнем уверенности:

![Разбор нормативного документа](docs/images/document-analysis.png)

Результат — **черновик**: он помечен статусом `draft`, в идентификаторе каждого правила стоит номер пункта исходного документа, а требования, которые не проверяются техническими средствами, вынесены в отчёт как организационные меры. Перед применением черновик нужно проверить и при необходимости поправить в конструкторе.

PDF не поддерживается: текст в нём хранится как набор глифов, и кириллица часто извлекается искажённой. Сохраните документ в DOCX или ODT.

### База знаний

«Справка и настройки» → «База знаний»: темы требований, которые распознаёт сервис, формулировки на русском и английском, документы, в которых темы встречаются, и число проверок, которые их закрывают.

![База знаний](docs/images/knowledge-base.png)

Номера пунктов зарубежных стандартов — ориентир: нумерация меняется между редакциями, сверьте со своей копией документа. База пополняется правкой файлов в `backend/knowledge/` и `backend/catalog/`.

### Редактирование и проверка

Любой элемент профиля изменяется кнопкой «Изменить» — идентификатор и ссылки на элемент сохраняются. На последнем шаге мастера встроенный валидатор проверяет связность и формат профиля перед выгрузкой.

![Проверка и экспорт](docs/images/validation.png)

## Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| Не найден python3 | Установите штатный пакет: `apt-get install python3` или `dnf install python3` |
| Требуется python3 версии 3.5 или новее | Обновите python3 средствами дистрибутива |
| Не найден openssl | Установите openssl либо ставьте сервис с `--no-tls` |
| Служба не запустилась | `journalctl -u compliance-profile-builder -n 50 --no-pager` |
| Сервис недоступен по сети | Проверьте, что порт открыт в межсетевом экране: `firewall-cmd --add-port=8443/tcp` или `ufw allow 8443/tcp` |
| Порт занят | Переустановите с другим портом: `--port 9443` |
| Импорт архива: «не найден XCCDF» | Сообщение перечисляет содержимое архива. Нужен XCCDF 1.1; XCCDF 1.2 и SCAP DataStream не поддерживаются |
| В документе не найдено пунктов | Требования должны быть оформлены нумерованным списком (1.1, 1.2…). Документ сохраните в DOCX или ODT |

## Проверка профилей средствами OpenSCAP

Выгруженный профиль можно проверить независимо:

```bash
oscap oval validate checks-oval.xml
xmllint --noout --schema /usr/share/openscap/schemas/xccdf/1.1/xccdf-schema.xsd benchmark-xccdf.xml
```

## Состав репозитория

```
backend/
  app/server.py       веб-сервер и REST API
  app/xmlcompat.py    работа с XML средствами стандартной библиотеки
  app/docimport.py    разбор нормативных документов, сборка черновика профиля
  app/knowledge.py    тезаурус требований, синонимы, приведение словоформ
  app/catalog.py      каталог типовых проверок
  app/*.py            построители XCCDF/OVAL, валидатор, экспорт и импорт ZIP
  catalog/            каталог проверок (JSON)
  knowledge/          база знаний: темы требований и синонимы (JSON)
frontend/             интерфейс (HTML, CSS, JavaScript, шрифт)
data/projects/        демонстрационные проекты (Windows и Astra Linux)
deploy/
  install.sh                          установка
  uninstall.sh                        удаление
  compliance-profile-builder.service  справочный вид systemd-юнита
  nginx.conf.example                  пример обратного прокси (необязательно)
docs/                 руководство пользователя и краткое описание (PDF), скриншоты
CHANGELOG.md          журнал изменений
USAGE.md              порядок создания профиля и разбор типовых ошибок
```
