# Compliance Profile Builder

Сервис для создания профилей соответствия в форматах **XCCDF 1.1** и **OVAL 5.11.2** для применения в продукте **Kaspersky Vulnerability Management**. Профиль собирается в браузере — пошаговым мастером, из каталога готовых проверок или автоматически по нормативному документу — и выгружается ZIP-архивом, который KVM импортирует без доработки.

Руководство пользователя с иллюстрациями и примеры нормативных документов поставляются отдельными файлами.

| Целевые ОС профилей | Linux: Astra Linux, РЕД ОС, Альт, SberLinux, Debian, Ubuntu; Windows 10, 11, Server 2016, 2019, 2022 |
| ОС сервера | Astra Linux, РЕД ОС, Альт, SberLinux, Debian, Ubuntu |
| Зависимости | Только стандартная библиотека Python 3.5+ |
| Каталог проверок | 87 технических проверок (73 для Linux, 14 для Windows) и 26 организационных мер |
| База знаний | 74 темы требований, 730 формулировок на русском и английском, 17 нормативных документов |
| Интерфейс | Русский и английский — включая каталог, базу знаний, описания правил и отчёты; светлая и тёмная тема |

## 1. Возможности

**Профиль соответствия** описывает, как должен быть настроен защищаемый узел, и позволяет KVM проверить это автоматически. Профиль — это ZIP-архив из двух частей:

- **`benchmark-xccdf.xml`** — требования человеческим языком: правила, их описания, ссылки на пункты нормативных документов, профили (наборы правил);
- **`*-oval.xml`** — техническая логика проверок: где искать (файл, параметр ядра, ключ реестра, пакет) и с чем сравнивать.

Вручную такой профиль пишется в XML со строгой схемой: одна проверка — пять связанных элементов и несколько десятков строк, одна опечатка — и KVM отклоняет архив целиком. Сервис заменяет это формами и автоматизацией.

| Возможность | Что даёт |
|---|---|
| **Мастер из десяти шагов** | Профиль с нуля без знания XML: шаги идут в порядке зависимостей элементов, на каждом — подсказка |
| **Конструктор** | Все разделы профиля сразу — для правки готового или импортированного профиля |
| **Каталог проверок** | 87 готовых технических проверок добавляются в проект одним действием, от переменной до правила |
| **Профиль по документу** | Загрузка приказа, стандарта или регламента (DOCX, ODT, TXT, MD) → разбор на пункты → тема и проверка для каждого пункта → черновик профиля |
| **Решения по пунктам** | Для каждого пункта документа — оставить проверку, выбрать другую, отнести к организационным мерам или исключить |
| **Отчёт о покрытии** | Готовый документ для заказчика: что проверяется автоматически, что выполняется организационно, что не сопоставлено |
| **«Что проверяется»** | Описание каждого правила человеческим языком: «Параметр ядра kernel.randomize_va_space = 2» |
| **Валидатор** | Проверка связности и формата перед выгрузкой с переходом к элементу, в котором ошибка |
| **База знаний** | Словарь требований: темы, формулировки, ссылки на документы; редактируется в интерфейсе |
| **Импорт** | Загрузка готовых профилей XCCDF 1.1 / OVAL для правки; профили ранних версий приводятся к схеме автоматически |

## 2. Системные требования

### Программное обеспечение

| Компонент | Требование |
|---|---|
| ОС сервера | Astra Linux SE 1.7 / 1.8, Astra Linux CE 2.12, РЕД ОС 8, Альт Сервер 10, SberLinux 8 / 9, Debian 11 и новее, Ubuntu 22.04 и новее. На других дистрибутивах Linux установка продолжится с предупреждением |
| Python | 3.5 и новее, только стандартная библиотека — сторонние пакеты не нужны |
| Служба | systemd (без него — ручной запуск, ключ `--no-service`) |
| openssl | Для выпуска самоподписанного сертификата. Не нужен с ключами `--no-tls` или `--cert` + `--key` |
| Браузер | Современный браузер; автотесты интерфейса выполняются в Chromium (Chrome, Edge, Яндекс Браузер) |

Сервис не содержит бинарных модулей и совместим с режимом замкнутой программной среды Astra Linux SE: установщик определяет этот режим и сообщает, что подпись файлов не требуется.

### Аппаратные ресурсы

Замерено на установленном сервисе:

| Показатель | Значение |
|---|---|
| Память процесса в покое | ≈ 23 МБ |
| Память при разборе документа | ≈ 25 МБ |
| Пять разборов документов одновременно | ≈ 26 МБ |
| Разбор документа из 49 пунктов | ≈ 0,7 с на одном ядре |
| Место на диске после установки | ≈ 1,5 МБ |
| Один проект | 15–40 КБ |

Рекомендуется: **1 ядро, от 512 МБ** памяти на систему целиком (запас — на загрузку крупных файлов: сервис принимает запросы до 50 МБ), **50–100 МБ** на диске с учётом проектов и журналов.

### Сеть

Один входящий порт: 8443 (HTTPS) или 8000 (HTTP) по умолчанию. Исходящих подключений сервис не устанавливает, доступ в интернет не нужен.

## 3. Установка

### Установка из ZIP

Предварительно необходимо скачать архив compliance-profile-builder-v1.0.0.zip из раздела Releases

```bash
unzip compliance-profile-builder-v1.0.0.zip
cd compliance-profile-builder
sudo bash install.sh
```

Сервис откроется по адресу `https://<адрес сервера>:8443/`. Браузер предупредит о самоподписанном сертификате — подтвердите исключение или установите свой сертификат (ключи `--cert` и `--key`).

### Что делает установщик

1. **Проверяет ключи** — порт (число от 1 до 65535), наличие файлов сертификата и ключа, что `--cert` и `--key` указаны вместе. Проверка выполняется **до любых изменений в системе**: при ошибке установка не начинается.
2. **Проверяет систему** — права root, ОС и архитектуру, наличие Python 3.5+, режим замкнутой программной среды.
3. **Копирует файлы** в каталог установки (по умолчанию `/opt/compliance-profile-builder`), включая скрипты `install.sh` и `uninstall.sh` — удалить сервис можно без исходного архива.
4. **Создаёт системного пользователя** `cpbuilder` без права входа в систему — служба работает от него, а не от root.
5. **Готовит сертификат**: устанавливает ваш, оставляет ранее выпущенный при повторной установке или выпускает самоподписанный с именем сервера и его IP-адресами.
6. **Создаёт службу** systemd `compliance-profile-builder` с ограничениями (`NoNewPrivileges`, `ProtectSystem`), запускает её и проверяет, что она поднялась.
7. **Печатает сводку**: каталоги, сертификат, адреса для подключения с сервера и по сети, команду удаления.

Все сообщения установщика и скрипта удаления выводятся **на русском и английском**.

### Ключи установщика

| Ключ | Назначение | По умолчанию |
|---|---|---|
| `--port <порт>` | Порт сервиса | 8443 для HTTPS, 8000 для HTTP |
| `--cert <файл>` | Свой сертификат HTTPS в формате PEM; указывается вместе с `--key` | самоподписанный |
| `--key <файл>` | Закрытый ключ к своему сертификату (PEM) | — |
| `--no-tls` | Работать по HTTP вместо HTTPS — например, за обратным прокси | — |
| `--host <адрес>` | Адрес прослушивания; `127.0.0.1` — только локальные подключения | `0.0.0.0` (доступен по сети) |
| `--cn <имя>` | Имя (Common Name) в самоподписанном сертификате | имя сервера |
| `--cert-days <дней>` | Срок действия самоподписанного сертификата | 825 |
| `--install-dir <путь>` | Каталог установки | `/opt/compliance-profile-builder` |
| `--user <имя>` | Системный пользователь службы | `cpbuilder` |
| `--no-service` | Только разложить файлы, без службы systemd; команда ручного запуска будет напечатана | — |
| `-h`, `--help` | Справка на русском и английском | — |

### Примеры

```bash
# нестандартный порт
sudo bash install.sh --port 9443

# сертификат корпоративного центра сертификации на порту 443
sudo bash install.sh --port 443 --cert /etc/ssl/cpb.crt --key /etc/ssl/cpb.key

# HTTP на локальном адресе — за обратным прокси (см. раздел 16)
sudo bash install.sh --no-tls --host 127.0.0.1 --port 8000

# без systemd, в свой каталог
sudo bash install.sh --no-service --install-dir /srv/cpb
```

TLS: принимаются только TLS 1.2 и новее.

## 4. Обновление и удаление

### Обновление

Распакуйте архив новой версии и запустите установщик **с теми же ключами**, что при первой установке:

```bash
sudo bash install.sh --port 9443
```

Установщик заменяет только код сервиса и перезапускает службу. **Проекты, правки базы знаний и сертификат сохраняются.** Если ключи не повторить, служба будет пересоздана с параметрами по умолчанию (порт 8443, HTTPS).

После обновления обновите страницу в браузере с очисткой кэша: Ctrl+Shift+R (macOS — ⌘+Shift+R). Если версии сервера и интерфейса расходятся, вверху страницы появится предупреждение с командой перезапуска службы.

### Удаление

```bash
sudo bash /opt/compliance-profile-builder/uninstall.sh
```

Скрипт показывает, что будет удалено, и запрашивает подтверждение. Затем останавливает и отключает службу, удаляет её из systemd, удаляет каталог установки, останавливает процессы пользователя `cpbuilder` и удаляет пользователя и его группу.

| Ключ | Назначение |
|---|---|
| `--keep-data` | Сохранить проекты и правки базы знаний в резервной копии |
| `--yes` | Не запрашивать подтверждение |
| `--install-dir <путь>`, `--user <имя>` | Если при установке они менялись |

## 5. Управление службой и данные

```bash
systemctl status compliance-profile-builder      # состояние
sudo systemctl restart compliance-profile-builder # перезапуск
journalctl -u compliance-profile-builder -n 100   # журнал
curl -k https://127.0.0.1:8443/api/version        # версия работающего сервера
```

| Путь (при установке по умолчанию) | Содержимое |
|---|---|
| `/opt/compliance-profile-builder/backend/` | Сервер, каталог проверок, база знаний |
| `/opt/compliance-profile-builder/frontend/` | Интерфейс |
| `/opt/compliance-profile-builder/data/projects/` | **Проекты**: XCCDF, OVAL-файлы, отчёты о покрытии |
| `/opt/compliance-profile-builder/data/knowledge/user-knowledge.json` | **Правки базы знаний** пользователей |

Каталог данных задаётся переменной окружения `CPB_DATA_DIR`; при установке она указывает на `data/` внутри каталога установки.

## 6. Интерфейс

- **Меню слева**: список проектов; группа «Создать из файла» — **Импорт ZIP…** и **Загрузить документ…**; группа «Справочники» — **База знаний** и **Справка и настройки**.
- **Шапка проекта**: название и идентификатор, кнопка **Отчёт о покрытии**, если проект собран по документу.
- **Два режима** — **Мастер** (десять шагов по порядку) и **Конструктор** (все разделы сразу). Данные общие, переключаться можно в любой момент.
- **Быстрый старт** при первом входе: назначение сервиса, порядок работы, настройки подсказок. Повторно — **Справка и настройки**.
- **Подсказки**: при первом открытии шага и всплывающие у полей форм; вопрос «Добавить ещё?» после создания элемента. Каждую можно отключить.
- **Язык** — RU / EN, **тема** — светлая и тёмная. Язык переключается целиком: подписи интерфейса, названия и описания проверок каталога, темы и разделы базы знаний, названия документов, решения и уверенность на экране разбора, описания «что проверяется», сообщения проверки проекта и отчёт о покрытии.
- **Язык профиля** — отдельная настройка: тексты правил создаются на языке бенчмарка (`xml:lang`). Черновик по английскому документу создаётся на английском (`en-US`), по русскому — на русском (`ru-RU`), независимо от языка интерфейса.
- **Компактные окна**: сервис работает в половине и четверти экрана — меню сворачивается, шаги мастера выстраиваются в одну строку.

## 7. Проекты

**Проект** — один профиль соответствия: бенчмарк XCCDF и один или несколько OVAL-файлов.

- **Создание** — кнопка **+** у заголовка «Проекты»: идентификатор (латиница, цифры, `-` и `_`, до 64 символов), идентификатор бенчмарка, заголовок, описание.
- **Список**: название проекта, идентификатор, пометка **черновик** для проектов, собранных по документу. При наведении — **✎ переименовать**, **⧉ копировать** (независимая копия с пометкой «(копия)»), **✕ удалить**. Когда проектов больше шести, появляется поиск.
- **Импорт ZIP** — загрузка готового профиля для правки. Принимаются архивы с файлами в корне, внутри одной папки («Сжать папку» в macOS и Windows) и со служебными файлами macOS. Профили, созданные вне сервиса или в ранних версиях, при выгрузке приводятся к схеме: восстанавливается порядок элементов и обязательные атрибуты. Формат XCCDF 1.2 и SCAP DataStream не поддерживается — такой архив отклоняется с объяснением.

## 8. Создание профиля в мастере

Каждый элемент профиля ссылается на предыдущий: **объект** говорит, где искать; **состояние** — с чем сравнивать; **тест** соединяет их; **определение** даёт проверке имя; **правило** превращает её в требование документа; **профиль** собирает правила в набор. Поэтому шаги идут в таком порядке:

| Шаг | Что задаётся |
|---|---|
| 1. Бенчмарк | Заголовок и описание профиля, язык, статус (черновик, промежуточный, принят, устарел), версия |
| 2. OVAL-файл | Контейнер технической части; имя дополняется окончанием `-oval.xml` автоматически. Ошибочно созданный файл удаляется прямо на шаге |
| 3. Переменные | Эталонные значения в одном месте — для использования в нескольких состояниях (необязательно) |
| 4. Объекты | Что проверяется: тип проверки и его поля (путь и шаблон файла, имя параметра, ключ реестра, пакет) |
| 5. Состояния | С чем сравнивать: операция (равно, не меньше, соответствует шаблону…), значение или ссылка на переменную, тип данных |
| 6. Тесты | Связка объекта и состояния; сколько объектов должно найтись (`check_existence`) и сколько из них совпасть (`check`) |
| 7. Определения | Законченная проверка с названием и описанием; один или несколько тестов; семейство ОС и платформы |
| 8. Правила | Требование документа: ссылка на определение и **идентификатор требования** — номер пункта исходного документа |
| 9. Профили | Набор правил для запуска; на одних узлах можно проверять разные наборы, например «Базовый» и «Усиленный» |
| 10. Проверка и экспорт | Валидация и выгрузка ZIP-архива |

Если на шаге нечего выбрать, мастер показывает, какой шаг нужно пройти раньше. Любой элемент правится без потери ссылок на него; при сбое правки элемент остаётся прежним.

### Семейство ОС и платформы определения

У определения (шаг 7) два похожих поля, которые нельзя путать:

- **family** — фиксированное значение стандарта OVAL: `windows`, `unix`, `linux` или `independent`. Мастер подставляет его по типу теста. Вписывать сюда название дистрибутива нельзя — файл перестанет соответствовать схеме.
- **platforms** — свободный список систем через запятую, для которых актуальна проверка: «Astra Linux, РЕД ОС». Под полем — кнопки быстрой вставки: РЕД ОС, ALT Linux, Astra Linux, Debian, Ubuntu, Windows.

### Типы проверок

| Тип OVAL | Что проверяет | Платформа |
|---|---|---|
| `ind:textfilecontent54_test` | Содержимое текстового файла по регулярному выражению | Любая |
| `ind:variable_test` | Значение переменной | Любая |
| `unix:file_test` | Атрибуты файла: права доступа, владелец, группа | Linux |
| `unix:password_test` | Учётная запись в /etc/passwd | Linux |
| `unix:sysctl_test` | Параметр ядра (sysctl) | Linux |
| `linux:dpkginfo_test` | Пакет DEB | Linux |

## 10. Профиль по нормативному документу

Сервис читает приказ, стандарт или внутренний регламент, разбирает его на пункты, определяет тему каждого требования и предлагает проверку. Результат — черновик профиля и отчёт о покрытии.

### Поддерживаемые документы

| Формат | Поддержка |
|---|---|
| DOCX, ODT | Да, включая автоматическую нумерацию пунктов из разметки списков |
| TXT, MD | Да |
| PDF | Нет: в PDF текст хранится набором глифов и часто извлекается искажённым. Сохраните документ в DOCX или ODT |

Распознаётся нумерация пунктов:

- **многоуровневая** — «2.4.1. Ограничить доступ…», в том числе в стиле CIS — «18.9.3 Turn on…»;
- **одноуровневая** — «21. Меры по идентификации…», как в приказах ФСТЭК;
- **автоматическая** — номер не хранится в тексте и восстанавливается из разметки списков DOCX и ODT.

Заголовки разделов («2. Парольная защита», римские «III. Требования к мерам…») становятся контекстом для пунктов. Пункт с подпунктами, заканчивающийся двоеточием («2.2 … необходимо:»), считается разделом, а не требованием.

### Порядок работы

1. Меню слева → **Загрузить документ…** → выбрать файл.
2. Проверить название документа (оно войдёт в идентификатор требования каждого правила), выбрать ОС, проверить идентификатор нового проекта — он предлагается по имени файла с транслитерацией.
3. **Разобрать документ** → экран разбора.
4. Для каждого пункта выбрать решение и нажать **Создать черновик профиля**.

### Экран разбора

Для каждого пункта: номер, начало текста, найденная **тема требования**, **решение** и **уверенность**.

| Уверенность | Как получена |
|---|---|
| Высокая | Пункт прямо ссылается на проверку из пакета документа (документ узнан по заголовку) |
| Средняя | В тексте найдена формулировка темы из базы знаний |
| Низкая | Найдено только частичное сходство |
| Нет | Тема не найдена |

| Решение | Результат |
|---|---|
| **Авто** | Предложенная проверка войдёт в черновик, если уверенность не ниже порога (по умолчанию — средняя) |
| Другая проверка | Выбранная проверка войдёт в черновик при любой уверенности |
| **Организационная мера** | Пункт попадёт в отчёт как организационная мера |
| **Исключить пункт** | Пункт не войдёт в черновик — например, введение или область применения |

### Что создаётся

- Бенчмарк со статусом **черновик** и предупреждением в описании.
- Правило для каждого пункта с проверкой; в идентификаторе — название документа и номер пункта. Если несколько пунктов закрываются одной проверкой, правило одно, а идентификаторов у него несколько.
- Профиль со всеми созданными правилами и отчёт о покрытии.
- **Язык профиля — язык документа**: по английскому документу бенчмарк, правила, описания определений, профиль и предупреждение о черновике создаются на английском (`xml:lang="en-US"`), по русскому — на русском. Язык определяется по большинству пунктов документа.

Черновик — отправная точка: перед применением сверьте каждое правило с пунктом документа и проверьте пути и эталонные значения для своей версии ОС.

### Примеры документов

Отдельным архивом поставляются четыре документа для пробы:

| Файл | Язык | ОС при загрузке | Пунктов |
|---|---|---|---|
| `windows-ru.docx` | RU | Windows Server 2019 | 15 |
| `linux-ru.docx` | RU | Astra Linux | 11 |
| `windows-en.docx` | EN | Windows Server 2022 | 14 |
| `linux-en.docx` | EN | Ubuntu | 10 |

Загрузите документ, выберите ОС из таблицы, создайте черновик и запустите **Проверить проект** — ошибок быть не должно. Тексты требований написаны своими словами по мотивам типовых документов: Рекомендаций ФСТЭК, CIS Benchmark, регламентов организаций.

## 11. Отчёт о покрытии

Сохраняется в проекте при сборке черновика. Открывается кнопкой **Отчёт о покрытии** в шапке проекта и скачивается **HTML-страницей** — самодостаточной, без внешних ресурсов, оформленной для печати и сохранения в PDF.

Содержание: документ, ОС, проект и дата; сводка — сколько пунктов, сколько проверяется автоматически (с долей в процентах), сколько правил в профиле, организационных мер, пунктов без сопоставления и исключённых; цветная полоса покрытия; таблица всех пунктов в порядке документа — статус и проверка или причина.

| Статус пункта | Значение |
|---|---|
| Проверяется автоматически | Создано правило; KVM проверит его на узлах |
| Организационная мера | Выполняется организационно, проверяется анализом документов и процессов |
| Без сопоставления | Подходящей проверки не найдено — пункт нужно разобрать вручную |
| Исключён при разборе | Исключён пользователем |

Отчёт фиксирует состояние на момент сборки черновика и в архив для KVM не попадает. Страница формируется на языке интерфейса, из которого её скачали: статусы, заголовки, названия проверок, причины и предупреждение — на русском или на английском.

## 12. Проверка и выгрузка профиля

**Проверка проекта** (шаг 10 мастера) находит то, из-за чего KVM отклонит архив, — и то, что стоит доделать:

| Уровень | Примеры |
|---|---|
| **Ошибка** | Нет бенчмарка или OVAL-файла; не заполнено обязательное поле; дубликат идентификатора; правило ссылается на несуществующее определение; тест — на несуществующий объект или состояние; объект другого типа; ссылка на несуществующую переменную; идентификатор не в формате OVAL |
| **Замечание** | Правило без идентификатора требования; профиль без правил; бенчмарк без профиля; определение без семейства ОС |

Кнопка **Перейти →** у сообщения открывает нужный шаг — при необходимости в другом OVAL-файле — и подсвечивает элемент.

### Типичные ошибки и как их исправить

| Сообщение | Причина | Как исправить |
|---|---|---|
| «Benchmark: не заполнено обязательное поле…» | Пустой заголовок, описание, статус или версия | Заполните поле на шаге «Бенчмарк» |
| «Profile/select ссылается на несуществующее правило…» | В профиле отмечено удалённое правило | Шаг «Профили» → **Состав** → снимите отметку или создайте правило заново |
| «Правило…: не задана ссылка check-content-ref» | У правила не выбраны OVAL-файл и определение | Шаг «Правила» → **Изменить** → выберите файл и определение |
| «Идентификатор… не соответствует формату oval:…» | Идентификатор не вида `oval:<namespace>:<тип>:<номер>` | Исправьте идентификатор элемента |
| «Идентификатор… не уникален в рамках комплекта файлов» | Один идентификатор использован дважды, в том числе в разных OVAL-файлах | Переименуйте один из дубликатов |
| «Тест…: object_ref не найден» / «state_ref не найден» | Тест ссылается на удалённый объект или состояние | Шаг «Тесты» → **Изменить** → выберите существующий элемент |
| «Тест… ссылается на object… несовместимого типа» | Тест и объект созданы для разных типов проверки | Используйте объект того же типа, что и тест |
| «State…: var_ref… не найден среди variables» | Состояние ссылается на удалённую переменную | Создайте переменную или измените ссылку |
| «criterion ссылается на несуществующий тест…» | Определение ссылается на удалённый тест | Шаг «Определения» → **Изменить** → выберите тест |

Ошибки (**ошибка**) не дают корректно импортировать архив; замечания (**замечание**) — рекомендации, выгрузке не мешают.

**Экспорт ZIP** выгружает `benchmark-xccdf.xml` и OVAL-файлы проекта. Файлы соответствуют схемам XCCDF 1.1 и OVAL 5.11.2: при выгрузке восстанавливаются порядок элементов и обязательные атрибуты. Для контроля перед загрузкой в KVM можно проверить файлы средствами OpenSCAP: `oscap oval validate checks-oval.xml`.

### Документы

Приказы ФСТЭК **№117** (ГИС, с 01.03.2026 вместо №17), **№21** (ПДн), **№31** (АСУ ТП), **№239** (КИИ); Рекомендации ФСТЭК **по безопасной настройке ОС Linux** (2022), **по типовым ошибкам конфигурации** (2026), **по регистрации событий** (2026); **ГОСТ Р 57580.1-2017**, **ГОСТ Р 59547-2021**; **CIS Benchmark**, **CIS Controls v8**; **NIST SP 800-53 Rev. 5**, **NIST CSF 2.0**; **ISO/IEC 27002:2022**; **PCI DSS v4.0**; **BSI IT-Grundschutz**; **DISA STIG**.

Номера пунктов со звёздочкой — ориентир: нумерация меняется между редакциями, сверьте со своей копией документа. Тексты стандартов в базе не воспроизводятся — хранятся обозначения пунктов и собственные формулировки-маркеры.

### Просмотр и отбор

- **Плашки документов** — фильтры. Можно выбрать несколько и показать темы, которые есть **хотя бы в одном** из выбранных документов, или **во всех сразу** — так видно, что общего у документов (например, у приказа №117 и PCI DSS — 26 общих тем).
- **Поиск** — по названиям, формулировкам, документам и номерам пунктов («аудит», «8.3.6», «ИАФ»).
- **Названия тем** открывают тему для правки, **названия разделов** отбирают темы раздела.
- **Язык**: в русском интерфейсе показываются русские названия тем, разделов и документов и русские формулировки, в английском — английские. Отбор и поиск работают одинаково в обоих режимах.

### Проверка формулировки

**Проверить формулировку** показывает, как сервис поймёт текст пункта: найденные темы, причину сопоставления и предложенную проверку с уверенностью. Для одного-двух слов, которых мало для уверенного распознавания, показываются темы, где эти слова встречаются, — с поиском по началу слова: «парольная» находит и «пароль», «ssh» — темы с проверками SSH.

### Редактор

- **Изменить тему**: добавить или скрыть формулировки, добавить ссылки на документы — в том числе на внутренние регламенты организации, — привязать проверки и организационные меры. Поставляемые формулировки не удаляются, а скрываются и могут быть возвращены; **Вернуть исходный вид** отменяет все правки темы.
- **Новая тема** — для требований, которых нет в поставляемой базе.
- **Язык в редакторе**: правятся формулировки на языке интерфейса; формулировки на другом языке сохраняются как были и видны после переключения языка. Название темы в английском режиме — английское: его можно задать и для своей темы.
- **Синонимы** — замены оборотов документа на обороты базы. Замена ищется как есть, без словоформ.

Правила хороших формулировок: 2–4 слова, характерные именно для темы; не длиннее 120 символов; добавлять стоит оборот, на котором сервис промахнулся.

### Хранение и перенос правок

Правки хранятся **отдельно** от поставляемой базы — только разница с ней, в `data/knowledge/user-knowledge.json`. Обновление сервиса их не стирает.

**Экспорт правок** и **Импорт правок** переносят наработки между серверами, позволяют делиться ими с коллегами и делать резервную копию перед экспериментами. При импорте правки тем из файла заменяют правки тех же тем, синонимы добавляются к имеющимся. Если файл ссылается на проверки, которых нет в каталоге сервера, импорт отменяется целиком.

## 14. Как работает распознавание требований

Нейросетей и внешних сервисов нет: алгоритм детерминированный, и каждое решение объяснимо.

1. **Чтение файла.** DOCX и ODT — это ZIP-архивы с XML. Сервис извлекает абзацы и восстанавливает автоматическую нумерацию из описания списков и стилей.
2. **Выделение пунктов** по формам нумерации (раздел 10); заголовки становятся контекстом пунктов.
3. **Нормализация**: замена синонимов, «ё» → «е», сведение слов к основам — «регистрацию событий» совпадает с «регистрация событий».
4. **Поиск темы**:
   - **точные совпадения формулировок** — основы слов формулировки идут в тексте подряд; имена файлов и пути (`.profile`, `/etc/shadow`) сравниваются буквально;
   - **частичное сходство** — доля общих слов, взвешенная по их редкости в базе, с порогом 0,45: одно случайное общее слово тему не находит.
5. **Выбор проверки**: учитываются связь с найденной темой, ключевые слова проверки в тексте и совпадение номера пункта с пакетом каталога — только если документ узнан по заголовку. Проверки, не подходящие выбранной ОС, отсекаются; при равенстве техническая проверка выигрывает у организационной меры.
6. **Уверенность** выводится из этих оценок (раздел 10).

База знаний пополняется по реальным документам: оборот, на котором сервис промахнулся, добавляется в нужную тему — в редакторе это может сделать любой специалист.

## 15. Безопасность

| Мера | Что защищает |
|---|---|
| **Проверка источника запросов** | Изменяющие запросы принимаются только со страниц самого сервиса (`Sec-Fetch-Site`, `Origin`) и только с правильным типом тела. Посторонняя страница, открытая в браузере пользователя, не может изменить данные |
| **Строгая политика безопасности контента (CSP)** | Интерфейс не содержит встроенного JavaScript; скрипты загружаются только с самого сервиса. Внедрённый скрипт браузер не исполнит |
| **Заголовки безопасности** | Запрет встраивания во фрейм (защита от подмены кликов), `Referrer-Policy`, `X-Content-Type-Options` |
| **Ограничения загрузки** | Запрос — до 50 МБ; архив — до 2000 файлов, до 64 МБ на файл и до 256 МБ в распакованном виде (защита от ZIP-бомб) |
| **Защита разбора XML** | Файлы с объявлениями DOCTYPE и сущностей отклоняются (защита от «взрыва сущностей») |
| **HTTPS** | TLS 1.2 и новее |
| **Целостность данных** | Атомарная запись проектов: сбой посреди записи не повреждает файл. Изменения выполняются по очереди — одновременная работа пользователей не теряет правки |
| **Изоляция службы** | Работает от непривилегированного пользователя с ограничениями systemd |

**Рекомендации**: сервис не разграничивает пользователей, поэтому ограничьте доступ к его порту межсетевым экраном или авторизацией на обратном прокси; используйте сертификат корпоративного центра сертификации.

## 16. Работа за обратным прокси

Сервис принимает изменяющие запросы только со своих страниц, поэтому прокси должен передавать исходный заголовок `Host`. Пример для nginx при установке с ключами `--no-tls --host 127.0.0.1 --port 8000`:

```nginx
server {
    listen 443 ssl;
    server_name profiles.example.local;
    ssl_certificate     /etc/ssl/certs/profiles.example.local.crt;
    ssl_certificate_key /etc/ssl/private/profiles.example.local.key;
    client_max_body_size 50m;           # сервис принимает файлы до 50 МБ

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Если прокси не передаёт `Host` и интерфейс сообщает «Запрос с другого сайта отклонён», укажите адрес, по которому пользователи открывают сервис:

```bash
sudo systemctl edit compliance-profile-builder
# [Service]
# Environment=CPB_ALLOWED_ORIGINS=https://profiles.example.local
sudo systemctl restart compliance-profile-builder
```

## 18. REST API

Интерфейс работает через REST API — 56 адресов. Изменяющие запросы требуют тела `application/json` (файлы — `application/octet-stream` или `application/zip`) и принимаются только с того же источника или без заголовков браузера (скрипты, `curl`).

| Группа | Основные адреса |
|---|---|
| Служебные | `GET /api/version`, `GET /api/oval-type-schemas` |
| Проекты | `GET /api/projects`, `GET /api/projects/overview`, `POST /api/projects`, `GET` и `DELETE /api/projects/{id}`, `POST /api/projects/{id}/copy`, `POST /api/projects/{id}/rename` |
| Импорт и экспорт | `POST /api/projects/import?project_id=…`, `GET /api/projects/{id}/export`, `GET /api/projects/{id}/validate` |
| Бенчмарк, правила, профили | `PUT /api/projects/{id}/benchmark`; `POST`, `PUT`, `DELETE` для `/rules` и `/profiles`; `PUT /profiles/{p}/select` |
| OVAL | `GET`, `POST`, `DELETE /api/projects/{id}/oval-files`; `POST`, `PUT`, `DELETE` для `/variables`, `/objects`, `/states`, `/tests`, `/definitions` |
| Каталог | `GET /api/catalog?os=…`, `POST /api/projects/{id}/catalog-checks` |
| Документы | `POST /api/documents/analyze`, `POST /api/documents/draft-from-analysis`, `POST /api/documents/draft` |
| Отчёты | `GET /api/projects/{id}/coverage`, `GET /api/projects/{id}/coverage/report`, `GET /api/projects/{id}/rules/summary` |
| База знаний | `GET /api/knowledge`, `POST /api/knowledge/test`, `GET` и `POST /api/knowledge/user`, `PUT /api/knowledge/synonyms`, `POST`, `PUT`, `DELETE /api/knowledge/concepts` |

Описания правил, проверка проекта и отчёт о покрытии принимают параметр `?lang=en` — ответ на английском; без параметра — на русском (отчёт о покрытии — на языке документа).

Пример — проверить и выгрузить проект из скрипта:

```bash
curl -k https://127.0.0.1:8443/api/projects/my_profile/validate
curl -k "https://127.0.0.1:8443/api/projects/my_profile/validate?lang=en"
curl -k -o my_profile.zip https://127.0.0.1:8443/api/projects/my_profile/export
```

Ошибки возвращаются в виде `{"detail": "текст"}`: 400 — ошибка в данных, 404 — нет проекта или адреса, 413 — слишком большой запрос, 415 — неверный тип тела, 422 — неверная структура или типы полей.

## 19. Устранение неполадок

| Симптом | Причина | Решение |
|---|---|---|
| Жёлтое предупреждение «Сервер работает на старой версии» | Файлы обновлены, служба не перезапущена | `sudo systemctl restart compliance-profile-builder` |
| Интерфейс выглядит старым после обновления | Браузер показывает интерфейс из кэша | Ctrl+Shift+R |
| «Запрос с другого сайта отклонён» | Обратный прокси не передаёт заголовок `Host` | Передайте `Host` или задайте `CPB_ALLOWED_ORIGINS` (раздел 16) |
| Ошибка 413 при загрузке через прокси | Лимит размера запроса в прокси меньше 50 МБ | `client_max_body_size 50m` в nginx |
| Установщик: «Неверный порт» / «Файл не найден» | Ошибка в ключах | Проверьте значение; в системе ничего не изменено |
| Служба не запустилась | Порт занят или неверный сертификат | `journalctl -u compliance-profile-builder -n 50` |
| Документ PDF отклонён | PDF не поддерживается | Сохраните в DOCX или ODT |
| В документе не найдено ни одного пункта | Буквенная нумерация («ИАФ.1») или пункты в таблице | Документ с цифровой нумерацией; пункты таблицы перенесите в текст |
| Пункт ушёл в неверную тему | В базе нет оборота, которым он сформулирован | Исправьте решение на экране разбора; добавьте оборот в нужную тему |
| «Проверить формулировку» не находит тему по одному слову | Одного слова мало для распознавания пункта | Смотрите список тем по слову или введите текст пункта целиком |
| Импорт отклонён: «XCCDF 1.2» | Формат не поддерживается | Используйте профиль XCCDF 1.1 |
| KVM отклонил архив | В профиле есть ошибки | **Проверка проекта**, устраните все ошибки |

## 20. Ограничения версии 1.0

- Законы со структурой «статья — часть — пункт» (например, 152-ФЗ) разбираются неверно: части разных статей сливаются. Для технического профиля по персональным данным используйте приказ ФСТЭК №21.
- Обозначения пунктов вида «ИАФ.1», «AC-7», «V-230221» и требования в таблицах не распознаются.
- PDF не поддерживается; импорт XCCDF 1.2 и SCAP DataStream не поддерживается.
- Нет разграничения пользователей и журнала их действий.

## English summary

**Compliance Profile Builder 1.0** is a web service that builds **XCCDF 1.1 / OVAL 5.11.2** compliance profiles for Kaspersky Vulnerability Management. Pure Python 3.5+ standard library, offline installation, Russian and English interface.

**Installation.** `sudo bash install.sh` — one command; all installer messages are in Russian and English. Options: `--port`, `--cert` + `--key` (your own PEM certificate), `--no-tls`, `--host`, `--cn`, `--cert-days`, `--install-dir`, `--user`, `--no-service`; see `bash install.sh --help`. Options are validated before any system change. Upgrade: rerun the installer with the same options — projects, knowledge base edits and the certificate are kept. Removal: `sudo bash /opt/compliance-profile-builder/uninstall.sh` (`--keep-data` keeps projects).

**Requirements.** Astra Linux, RED OS, ALT, SberLinux, Debian or Ubuntu with systemd; 1 CPU core, 512 MB RAM for the whole system (the service itself uses about 25 MB), 50–100 MB of disk space; no internet access.

**Features.**
- **Ten-step wizard** in dependency order and a **constructor** with all sections at once; 18 OVAL check types for Linux and Windows.
- **Catalog of 87 ready-made checks** (73 Linux, 14 Windows) added in one action, OS-aware defaults (DEB/RPM packages, GRUB paths), range checks, automatic rollback on failure; 26 organisational measures.
- **Draft profiles from requirement documents** (DOCX, ODT, TXT, MD): multi-level, single-level and automatic numbering; per-clause topic, confidence and decision (keep, choose another check, organisational measure, exclude); one rule may cover several clauses.
- **Coverage report** — a self-contained printable HTML page for the customer.
- **Human-readable rule descriptions** and a **validator** with jump-to-element.
- **Knowledge base**: 74 requirement topics, 730 phrasings in Russian and English, references to 17 documents (FSTEC orders 117, 21, 31, 239 and recommendations, GOST, CIS, NIST, ISO/IEC 27002, PCI DSS, BSI, DISA STIG); multi-document filtering (any / all), word search, phrase tester; an editor for phrasings, references, custom topics and synonyms; edits are stored separately and survive upgrades, with export and import.
- **Deterministic, explainable recognition** — no AI or external services.
- **Security**: same-origin checks for state-changing requests, strict Content Security Policy (no inline JavaScript), anti-framing headers, upload limits against ZIP bombs, XML entity protection, TLS 1.2+, atomic writes, serialized edits, unprivileged service user.
- **REST API** with 56 endpoints used by the interface and available to scripts.

**Language.** The interface switches between Russian and English completely: catalog checks, knowledge base topics, sections and documents, decisions and confidence on the review screen, rule descriptions, validator messages and the coverage report. The profile language is separate: a draft from an English document is created in English (`xml:lang="en-US"`), and catalog checks follow the benchmark language. API: `?lang=en` for rule summaries, validation and the coverage report.

**Examples and guide.** Sample requirement documents (Windows and Linux, Russian and English) and the user guide (DOCX) are distributed separately.

**Limitations.** Laws structured as article–part–item (e.g. 152-FZ), letter-style clause identifiers (ИАФ.1, AC-7, V-230221), requirements inside tables, PDF input and XCCDF 1.2 / SCAP DataStream import are not supported in 1.0. No per-user access control — restrict network access to the service.
